# Проверка мультиков без iPhone

Нужно: `npm i playwright` (в среде Claude Chromium уже есть) и three.js в `Resources/Mebel` — как в CI:
`npm pack three@0.169.0 && tar xzf three-0.169.0.tgz && cp package/build/three.module.min.js Resources/Mebel/`

- `node render.js halloween.txt 5 30 120` — разобрать сценарий (или серию .json) и снять кадры на 5-й, 30-й, 120-й секунде.
- `node render.js halloween.txt --hq --out=kadry 30` — то же в режиме «как в кино» (медленно, до 2–3 мин на кадр).
- `node sheet.js` / `node sheet.js hq` — все предметы на одном листе.
- `node places.js сценарий.txt --hq [--w=960] [--out=папка] [--at=0.5] [--only=2,5]` — по кадру из каждой сцены (место и время в имени файла). Удобно для проверки всех мест «как в кино»: сценарий из сцен «луг, день», «улица, ночь», «кухня, вечер»… с героями и `КАМЕРА: общий план` (или `крупно Барсик` — проверить размытый фон).
- В «как в кино» Барсик — «неоновая основа» (`multik-barsik.js`, данные `Resources/Mebel/barsik/`): frame.html грузит их сам (`frame.html#hq`). Сборка данных — `tools/multik/barsik/README.md`.

- БАРС (`tools/bars/README.md`): в «как в кино» frame.html сам готовит Пика и Рона образца 6.2 (шерсть + свет, облегчённое запекание). `H6=noh6` — без них, `H6=h6full` — запекание как в телефоне. `EVAL='…'` — выполнить в странице перед кадрами (например `BARSSoty.on=false` — старая трава, `MKBarsik.shellU.value=0` — без налёта), `EVAL2='…'` — после кадров (печатает JSON).

- `node audio.js laugh.txt [frame-audio.html]` — с `frame-audio.html` работает без three.js (только звук: смех из банка `Resources/Mebel/laugh/`, печатает `bank:<id>` у каждого смеха); озвучка без телефона: голос iPhone заменён ровным подставным звуком, а смех, «(смеясь)», «Ха-ха» в реплике и «ЗВУК: смех» собираются по-настоящему; печатает каждую реплику, её начало, длину и громкость в сведённой дорожке (0 — тишина, значит звук потерялся).

- `node homo.js` — омографы для голосов iPhone (з+амок/зам+ок по смыслу): поднимает http над Resources/Mebel, гоняет `MKVoice.homoMarks` по проверочным фразам и печатает IPA, который уйдёт в iPhone. Нужны `voice/homo.json`, `homo_emb.q8`, `homo.onnx` и `ort/` из ветки multik-voice (`git show origin/multik-voice:voice/homo.json > Resources/Mebel/voice/homo.json` и т. д.; в git не коммитить).
- `node build.js` — фоновая сборка: очередь из нескольких серий, полоска внизу, обрыв куска видео (как при сворачивании) и перерисовка этих кадров, ошибка → «Продолжить сборку» с того же кадра, отмена. В конце каждая серия должна дать все кадры (`ends` = число кадров).

- `node rech.js` — ударения нейроголосов путём телефона: 422 фразы с известным ударением, должно быть 422 из 422 (`--old` — как было, 363). `node golos.js same <Resources/Mebel прежней сборки>` —
  обычные реплики обязаны совпасть с прежней сборкой один в один. Подробно — `tools/multik/OZVUCHKA.md` (БАРС-озвучка). Обе проверки — перед установкой, если трогали озвучку.

Сам голос iPhone, его ударения и запись смеха микрофоном здесь проверить нельзя — только на телефоне.

## Проверка перед установкой на телефон (обязательно)
`node tools/multik/test/smoke.js` — «Просмотр» короткой серии (`smoke.txt`: лес и дом, трое героев, рассказчик) на настоящей странице
multik.html, «как в кино», с нейроголосом. Проверяет: нет ошибок; «▶ Послушать» рассказчика звучит и ставит ударения; просмотр
открывается; все реплики рассказчика — нейроголосом; рамка с голосом убрана перед 3D; память после озвучки вернулась
(не больше +280 МБ сверх начала — у сборок 35–36 голос оставался в странице, было +450…550, и на телефоне просмотр обрывался);
пик памяти на 3D-сценах не больше 900 МБ (до нейроголоса было ~720). Голос, как в телефоне, идёт в отдельном процессе
(в телефоне — скрытая страница MultikVoiceHost, тут — отдельная вкладка); `--iframe` — проверить запасной путь с рамкой.
В конце — «можно ставить» или «НЕ СТАВИТЬ».
Файлы голоса берутся из `Resources/Mebel/voice|ort` или из клона ветки `multik-voice` (`--voice=папка`). Около минуты.
