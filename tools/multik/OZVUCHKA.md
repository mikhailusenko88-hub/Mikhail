# БАРС-озвучка

Произношение и голоса «Мультиков». Ветка `bars-ozvuchka` (на утверждении у Михаила — в `mebel-3d` не вливать и на телефон не ставить, пока он не скажет).

## Что это
1. **Произношение — один «мозг» для всех голосов** (`Resources/Mebel/multik-bars-rech.js`, `BARSRech`).
   Путь текста: словарь пользователя → числа словами → словарь исправлений → **грамматика** → омографы по смыслу (нейросеть) → модель ударений.
   - Грамматика (`BARSRech.rule`) решает раньше нейросети: «из до́ма / высокие дома́ / сидели до́ма», «в лесу́ / к ле́су», «на двери́ / все две́ри»,
     «две руки́ / мои ру́ки», «светятся глаза́», «выпил воды́», «уже́ темнее / стала у́же», «она начала́ петь / с самого нача́ла», «у ворот старого за́мка».
   - **«Все» или «всё»** (и остальные 180 пар «е/ё»: «небо/нёбо», «узнает/узнаёт», «во всём / всем привет»). Нейросеть читала «все» как «всё» в половине случаев
     («и всё засмеялись», «съел всё конфеты»). Теперь: сначала грамматика (`vse`), потом правило автора — если в реплике или в серии ставят «ё»
     (`MK.usesYo` → `lex.yo` → `BARSRech.yo`), слово через «е» читается как написано. Текст без «ё» (набран или надиктован на телефоне) — грамматика, потом нейросеть.
   - **Словарь и живая речь расходятся — решает Михаил на слух.** 10.11.2026: «возле двери́» — правильно, «возле две́ри» (как в словарях) — нет.
     Поэтому слова `L3_LIVE` (двери, печи, тени, степи, цепи, оси, мели) после «у, возле, из, от, до, к» правила не трогают — остаётся как было.
     Строго по словарю: `BARSRech.strict = true`. Новое правило ударения, где словарь спорит с привычным, — сначала образец Михаилу.
   - Нейросети омографов даётся только своё предложение (соседнее её сбивало).
   - Голоса iPhone: `MKVoice.homoMarks` считается в процессе голоса (страница voice.html). Функцию добавили 3 ноября 2026, но в странице приложения её не было с самого начала
     (прокси `window.MKVoice` её не отдавал) — у Пика, Рона и остальных героев с голосом iPhone омографы не разбирались вообще.
2. **Управляемый нейроголос** (`Resources/Mebel/multik-bars-golos.js`, `BARSGolos`). В `MKVoice.chunk` есть «режиссёр» (`o.shape`): можно задать
   длительность и высоту каждого звука модели. На этом построены:
   - смех голосом героя в ритме, мелодии и громкости настоящего смеха (шаблоны сняты с банка смехов, `G.LAUGHS`);
   - протяжные слова: «Ура-а-а!» (раньше читалось «ура, а, а», «Не-е-ет» — «не, е, ёт»);
   - звуки голосом героя: «Мяу!», «Мур-р-р», «Гав-гав», «Пи-пи-пи», «Ку-ку», «Му-у-у», «Бе-е-е», «Ква-ква», «Кря-кря», «Кар», «Ку-ка-ре-ку», «И-го-го»,
     «Ж-ж-ж», «Ш-ш-ш», «Тс-с», «М-м-м», «А-а-а», «Апчхи», зевок, плач, «Ля-ля-ля» по нотам (`G.SOUNDS`, `G.SOUND_WORDS`);
   - паспорт голоса: тон (P) и тембр (F) раздельно — модель говорит ниже и медленнее в F раз, запись ускоряется в F раз (без растяжки звука);
     живость интонации (R), эмоции (`G.EMO`), паузы на знаках не длиннее заданного (`pause`: у голоса nurgul запятая тянулась 1,3 с).
   - тип фразы по частям (`bars.typeFix`, только модель xenia): «…и шёпотом спросил: Пик, ты слышишь?» — раньше вся фраза считалась вопросом «когда…?» по первому слову,
     и «ты слышишь?» звучало ровно (−0,6 пт); с правкой рассказ до двоеточия — рассказ, после — вопрос (+2,6 пт). По умолчанию выключено, ждёт решения на слух (проба Д3).
   Вызов: `MKVoice.speak(text, { model, speaker, lex, bars: {…} })` — обычный JSON, проходит через мост iPhone (MultikVoiceHost), Swift менять не надо.

## БАРС-актёр: голос играет эмоцию (10.11.2026, выключено — ждёт решения на слух)
Было: эмоция реплики («Барсик (испуганно): …») только сдвигала весь голос — тон ×0,92–1,12, темп ×0,88–1,15. Распознаватели эмоций слышат такие реплики как ровную речь
(92–98 % «нейтрально» на фразах без эмоциональных слов).
Стало (`BARSGolos.ACT`, `actShape`, `fx`): у эмоции свой рисунок — высота и размах мелодии, наклон фразы, нажим на ударных слогах и на главном слове (`keyWord`), темп, паузы;
тембр светлее/глуше, дрожь голоса, дыхание, надрыв; шёпот (`G.whisper` — шум через «форму рта» звука, линейное предсказание) и крик. Эмоции: happy, surprised, scared, sad, cry, angry,
sleepy, love, shy, laugh + подача из ремарки `step.manner`: «(шёпотом)» → whisper, «(громко)», «(кричит)» → shout.
- **Рисунок — цель, а не прибавка.** Модель сама читает восклицания живее ровного текста; первая версия прибавляла поверх и переигрывала (размах 16 пт, UTMOS 3,3 → 2,5).
  Теперь высота тянется к цели (`reg − 0,7·средняя фразы`), размах — к `span`, главное слово не поднимается, если уже выделено, и есть мягкий предел +10/−8 пт.
- Включение: `lib.settings.bars.act = true` (`MK.barsAct`). Тогда реплики Барсика с эмоцией идут через БАРС (`srv.bars.emo`), прежний сдвиг тона/темпа для них отключается;
  герои с паспортом `c.golos` — так же. Громкость: шёпот ×0,7, крик ×1,25, грусть ×0,85 (`fx.level` в `MK.voiceFx` после выравнивания). Пик и другие голоса iPhone — как были.
- Свой рисунок без правки кода: `bars.actx = {reg, R, span, …, fx: {…}}`; сила игры `bars.k` (1 — как записано).
- Проверка: ветка `golos`, workflow `golos-emo` (`emo_request.txt`): `emo/*.flac + .txt` → `emo_out/report.md` — два распознавателя эмоций (HuBERT/Dusha: neutral, angry, positive, sad;
  wav2vec2/RESD: 7 эмоций), звуки AudioSet (шёпот, крик, плач), слова (Whisper), UTMOS, высота, размах, темп, яркость.
- Что приборы подтверждают, а что нет (итоговые рисунки): радость — «positive» 0,29 на ровных фразах против 0,03 без игры; удивление — 0,69 против 0,34 на реплике «Ого! Это же карта клада!»;
  сценка из шести реплик — «neutral» 0,66 → 0,35, «positive» 0,29 → 0,62, слова 100 %, UTMOS звучащих реплик 3,33 → 3,07; испуг — частично (fear 0,24 на ровных фразах, дрожь стоит ~0,4 балла UTMOS);
  высокий тон через саму модель смазывает слова («нашли клад» → «наш веклад») — у радости часть высоты даёт тембр (`fx.F: 1.03`), это обязательно;
  грусть, сонность, плач распознаватели эмоцией не называют, хотя голос измеримо ниже, медленнее и глуше; злость узнаётся слабо; шёпот: тона нет, слова распознаются все,
  но распознаватель звуков «шёпотом» его не называет. Последнее слово — за слухом Михаила (пробы Э0–Э11).

## Что не меняется
Обычные реплики Барсика (xenia, тон ×1,12, темп ×0,9286), Пика и остальных героев с голосом iPhone, рассказчика — звук тот же до отсчёта.
Через БАРС идут только: смех героя с нейроголосом (`MK.barsLaugh`), реплики с протяжными словами и звуками (`BARSGolos.needs`), герои с паспортом `c.golos`.
Смех по-старому: `lib.settings.bars = { oldLaugh: true }`.

## Проверка без телефона (обязательно перед установкой)
- `node tools/multik/test/rech.js` — 422 проверочные фразы с известным ударением (из них часть — настоящие реплики серий 4, 9, 10, 21). Должно быть 422 из 422.
  `--old` — как было до БАРС-озвучки (366 из 422; из 56 ошибок 25 — «все» прочитано как «всё»). `--strict` — строго по словарю («возле две́ри»).
- Длинная фраза с разными интонациями (вопрос шёпотом, заминка, выбор «или», крик, перечисление): `tools/multik/test/dlin.txt` — ею проверять новые голоса.
  Она же нашла ошибки «всё вместе», «у ворот замка́» (рядом слово «ключ») и слишком длинные паузы голоса nurgul.
- `node tools/multik/test/golos.js same <папка Resources/Mebel прежней версии>` — серия `golos.txt`: обычные реплики обязаны совпасть один в один
  (ключ, голос, параметры); по-новому идут только смех Барсика и реплики с «Ура-а-а» / «Мяу».
- Звук: ветка `golos` (без кода приложения), workflow `golos-check`: речь из `in/*.flac + .txt` — анализатор (слова, ударения, UTMOS),
  звуки из `snd/` — распознаватель AudioSet (смех это или речь). Workflow `golos-ep` — «послушать» готовую серию (`ep_request.txt`).
  С музыкой под голосом ударения в готовых сериях анализатор определяет ненадёжно (много ложных тревог) — верить только тексту расшифровки.
- YouTube с серверов GitHub не скачивается («подтвердите, что вы не робот»). Звук серии берётся в браузере Мака: `video.captureStream()` + MediaRecorder
  на скорости ×2 (`preservesPitch = false`), сохранение через ссылку `download` — файл появляется в «Загрузках» как скрытый
  `.Q6L2SF6YDW.com.anthropic.claudefordesktop.*`; потом `asetrate=24000` возвращает скорость.
