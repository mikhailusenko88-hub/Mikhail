# Бот магазина «Пространство» — Telegram и MAX

Бот магазина декора ARTDEC в Санкт-Петербурге: реечные панели, панели под дерево и бетон,
молдинги, плинтусы, карнизы, уголки. Работает на сервере Selectel (Ubuntu 24.04), который
настроен скриптом `setup-prostranstvo.sh` из этой же ветки.

Один и тот же бот работает в двух мессенджерах — **Telegram** и **MAX**. Сценарии одинаковые,
база общая, но это две отдельные службы: если один мессенджер недоступен, второй работает.

## Установка — одна команда (от root)

Токены необязательны и независимы — можно поставить только один мессенджер, второй добавить потом.

```
curl -fsSL https://raw.githubusercontent.com/mikhailusenko88-hub/Mikhail/server/bot/install-bot.sh | bash -s -- --tg 'ТОКЕН_TELEGRAM' --max 'ТОКЕН_MAX'
```

- только MAX: `… | bash -s -- --max 'ТОКЕН_MAX'`; только Telegram: `… | bash -s -- --tg 'ТОКЕН'`
  (старый вызов с одним токеном `… | bash -s -- 'ТОКЕН'` — тоже Telegram);
- **обновить** бота (токены, настройки и заявки не трогаются): `curl -fsSL …/install-bot.sh | bash`;
- выключить мессенджер: `--tg -` или `--max -`; новый код для `/owner`: `--new-code`;
- адрес сайта для ссылок: `--site-url https://ДОМЕН` (`-` — без ссылок; по умолчанию берётся домен
  из `/etc/prostranstvo/prostranstvo.conf`);
- заявки с телефоном в Telegram: `--tg-contacts 1` (см. «Telegram и персональные данные»).

С iPhone: «Команды» → своя команда «Сервер» (SSH на сервер Selectel) → вставить команду выше.
В конце установщик показывает ссылки на ботов и одноразовый код `/owner`. Токены он не печатает.

## Для владельцев: как завести бота в MAX

По документации MAX (dev.max.ru, разделы «Подключение к платформе» и «Создание и модерация чат-бота»).
Ботов в MAX могут создавать только юрлица, ИП и самозанятые — резиденты РФ.

1. **Профиль ИП на платформе «MAX для партнёров»** — `business.max.ru/self` (или мини-приложение
   «MAX для бизнеса» в MAX): вход по номеру телефона и коду из SMS → создать профиль ИП.
2. **Верификация ИП** — делает сама владелица ИП (или представитель с правом первой подписи):
   - через **Госуслуги**: у ИП должен быть личный кабинет на Госуслугах, вход — с ролью
     «Руководитель» или «Администратор» (роль «сотрудник» не подойдёт), данные ЕГРИП — актуальные
     (обновить: «Профиль организации» → «Данные организации» → «Обновить», обычно до часа);
   - или **через банк**: T-Business ID или Alfa ID (пока только в веб-версии платформы).
   Об успехе сообщит бот «MAX для бизнеса». Если не получается — чат «Поддержка MAX для бизнеса»
   (`max.ru/business_support_bot`) или `partner_support@max.ru` (ИНН, телефон, что делали, скриншот).
3. **Карточка бота**: раздел «Чат-боты» → «Создать»:
   - логотип — 500×500 px, до 5 МБ, .jpg/.png;
   - название — 1–59 символов, буквы и цифры, без эмодзи (например «Пространство — декор для стен»);
   - описание — до 200 символов, должно соответствовать деятельности ИП (например: «Реечные панели,
     молдинги, плинтусы ARTDEC в Санкт-Петербурге. Расчёт стены, цены, заявка менеджеру»);
   - ник присваивается сам, вида `idИНН_bot`, выбрать или поменять его нельзя; ссылка на бота —
     `max.ru/idИНН_bot`. У ИП может быть до 5 ботов.
4. **Модерация** — до 48 часов в рабочие дни (статус «На модерации»). Проверяют: без мата, 18+ и
   чужих данных, описание соответствует деятельности. Итог — «Опубликован» или «Нужны исправления»
   (причина — в карточке бота). Любая правка «Основной информации» отправляет бота на повторную
   модерацию; пока она идёт, клиенты видят прежнюю версию.
5. **Токен** — после модерации: «Чат-боты» → у бота **⋮ → «Настройки»** → значок «копировать» у поля
   токена. Токен никому не пересылать и не выкладывать; если есть сомнения — там же значок
   «обновить» (затем установщик с новым `--max 'ТОКЕН'`).
6. Запустить установщик с `--max 'ТОКЕН'` — бот в MAX заработает за минуту.

## Команда магазина: роли и подключение

| Роль | Что получает | Что может |
|---|---|---|
| **менеджер** | все сообщения клиентов, заявки, статусы отгрузок | отвечать клиентам, «Передать на отгрузку», приглашать и убирать людей, статистика |
| **отгрузка** | заявки и карточки «На отгрузку» (все сообщения — по желанию) | «Принял», «Отгружено», читать переписку, отвечать клиенту |

1. **Менеджер**: открывает бота (в MAX или в Telegram), «Начать», отправляет `/owner КОД` — код показал
   установщик. Код одноразовый: кто первым отправит, тот и менеджер.
2. **Отгрузка**: менеджер нажимает «Команда» → «Пригласить на отгрузку», бот даёт код на 24 часа (и ссылки
   на ботов). Второй человек открывает бота в своём мессенджере и отправляет `/join КОД`.
3. **Второй мессенджер для себя** (например, начали в Telegram, хотите и в MAX): «Уведомления» →
   «Подключить MAX» → код → в MAX отправить `/join КОД`. Это тот же человек, не новый сотрудник.
4. **Куда приходят заявки и сообщения**: в мессенджер, где человек подключён; если в обоих —
   по выбору в «Уведомлениях» («Присылать в MAX / в Telegram»), по умолчанию — **в MAX**.
   Там же: «Все сообщения клиентов» или «Только заявки и отгрузки» (у отгрузки по умолчанию так).
5. «Команда» — список (у каждого номер №…) и кнопки «Убрать» (`/remove №`). Последнего менеджера
   убрать нельзя.

**Ответ клиенту**: ответить («Ответить» / смахнуть влево) на его сообщение, заявку, карточку
или «Переписку» и написать текст — бот отправит его от имени магазина **в тот мессенджер, откуда
писал клиент** (из MAX можно отвечать клиенту из Telegram и наоборот). Фото и файлы
пересылаются только внутри одного мессенджера. Команды: `/reply 12 текст` (12 — номер заявки)
или `/reply К5 текст` (К5 — номер клиента), `/history 12` или `/history К5`.

### Отгрузка

Статусы заявки: **новая → подтверждена → на отгрузке → отгружено**.

1. Под заявкой у менеджера — «Передать на отгрузку». Бот спрашивает: что отгрузить (по умолчанию —
   расчёт из заявки), адрес или «Самовывоз», когда, телефон получателя (по умолчанию — из заявки).
   Менеджер проверяет и подтверждает — статус «подтверждена».
2. Карточка «На отгрузку №…» приходит всем с ролью «отгрузка» (каждому в его мессенджер) с кнопками
   «Принял» (статус «на отгрузке») и «Отгружено».
3. Менеджеру приходит сообщение о каждом статусе. «Отменить отгрузку» — только у менеджера.
4. «Отгрузки» (`/orders`) — что сейчас не отгружено.

## Telegram и персональные данные

Серверы Telegram — за границей, поэтому, пока не подано уведомление в Роскомнадзор о трансграничной
передаче персональных данных, Telegram-бот работает **без сбора контактов**
(`TELEGRAM_COLLECT_CONTACTS=0`, так по умолчанию):

- считает стену, показывает каталог и цены, принимает вопросы;
- вместо заявки с телефоном даёт ссылки: заявка на сайте (`ДОМЕН/#order`) и бот в MAX; кнопка
  «Продолжить в MAX» открывает в MAX тот же расчёт, откуда его можно отправить менеджеру;
- сотрудникам о сообщении из Telegram приходит только «Новое сообщение в Telegram — клиент К5,
  откройте /history К5» — без имени, телефона и текста; переписку смотрят в боте MAX;
- в чатах сотрудников **в Telegram** имена, телефоны, адреса и тексты клиентов не показываются
  («скрыто — смотрите в MAX»), отгрузку с адресом оформляют в MAX.

Включить приём заявок в Telegram (после уведомления РКН): установщик с `--tg-contacts 1`.

## Для клиентов (в обоих мессенджерах)

- **Рассчитать стену**: группа → артикул (кнопки или текстом, например `A907`) → размеры.
  Панели: `штук = ceil(ширина / ширина_панели) × ceil(высота / длина_панели)` + 7 % запаса (вверх).
  Погонаж: `штук = ceil(метры × 1,07 / длина_планки)`. Ввод: «3,2», «3.2», «320 см», «3200 мм»,
  сразу «3,2 x 2,7». Ответ: штуки, полные коробки + остаток поштучно, ориентировочная сумма.
- **Каталог и цены**: цена за штуку и за коробку; ссылка на сайт, если он задан.
- **Оставить заявку** (MAX; Telegram — при `TELEGRAM_COLLECT_CONTACTS=1`): имя → контакт («Отправить
  номер», телефон текстом или «Напишите мне в …») → комментарий → согласие на обработку
  персональных данных. Без «Согласен» ничего не сохраняется.
- **Связаться с менеджером** или просто сообщение в чат — уходит команде магазина.
- `/delete_me` — клиент сам удаляет свои заявки и переписку (отзыв согласия). Заказы, уже
  переданные на отгрузку, остаются — их хранят по договору и закону.
- Ссылки с сайта: Telegram `https://t.me/ИМЯ_БОТА?start=calc`, MAX `https://max.ru/idИНН_bot?start=calc`
  (также `catalog`, `lead`, артикул — например `A907`).

## Как это устроено

| Файл | Что внутри |
|---|---|
| `core.py` | все сценарии: клиенты, роли, отгрузки, очередь доставки — без привязки к мессенджеру |
| `tg.py` | Telegram (aiogram 3) |
| `max_api.py` | MAX: свой тонкий клиент Bot API на aiohttp |
| `calc.py`, `catalog.py`, `db.py`, `texts.py`, `config.py` | расчёт, каталог, база, все тексты, настройки |
| `bot.py` | запуск: `bot.py --channel tg` или `--channel max` |

- **Две службы**: `prostranstvo-bot` (Telegram) и `prostranstvo-max` (MAX). Общие база, каталог
  и `bot.env`. Сообщение в «чужой» мессенджер (например, ответ из MAX клиенту в Telegram) идёт через
  очередь в базе: каждая служба доставляет только в свой мессенджер, поэтому сбой одного мессенджера
  не мешает другому, а очередь дожидается его восстановления.
- **MAX API**: `https://platform-api2.max.ru`, токен в заголовке `Authorization`, события — long
  polling (`GET /updates`, отметка `marker` хранится в базе, после перезапуска события не
  обрабатываются дважды), не больше 2 сообщений в секунду в один диалог. Webhook не нужен (он
  требует домен с HTTPS); MAX рекомендует webhook для больших нагрузок — для магазина хватает
  long polling, перейти можно позже.
- **Сертификат Минцифры**: сервер API MAX подписан «Russian Trusted Sub CA», которого нет в обычном
  хранилище Ubuntu. Бот доверяет `certs/russian_trusted_ca.pem` (Russian Trusted Root CA и Sub CA,
  отпечатки SHA-256 — в файле и в тестах) **только для запросов к MAX**; системные сертификаты
  сервера не меняются. Промежуточный сертификат действует до 06.03.2027, корневой — до 27.02.2032;
  когда Минцифры выпустит новый промежуточный, его нужно будет добавить в этот файл.
- **Почему свой клиент MAX, а не библиотека**: живая библиотека есть (maxapi на GitHub, версия 1.2.3,
  один автор, лишние зависимости), но боту нужно 8 методов API — их проще держать под контролем.

## Где что лежит на сервере

| Что | Где |
|---|---|
| код бота | `/opt/prostranstvo-bot/app` (копия папки `bot/` ветки `server`) |
| Python и библиотеки | `/opt/prostranstvo-bot/venv` |
| настройки и токены (секретно, chmod 600) | `/etc/prostranstvo/bot.env` |
| база: клиенты, заявки, отгрузки, переписка, команда, очередь | `/var/lib/prostranstvo/bot.db` (только на сервере) |
| кеш каталога | `/var/lib/prostranstvo/bot-catalog.json` |
| службы | `systemctl status prostranstvo-bot prostranstvo-max` |
| журналы | `journalctl -u prostranstvo-bot -n 50`, `journalctl -u prostranstvo-max -n 50` |
| журнал установки | `/var/log/prostranstvo-bot-install.log` |

База первого выпуска (только Telegram) при первом запуске сама переводится на новую версию —
заявки, переписка, отгрузки и команда сохраняются.

Каталог и цены — из массива `const CAT=[...]` в `index.html` сайта: сначала
`/var/www/prostranstvo/index.html`, если не вышло — GitHub (ветка `mebel`), потом последняя
удачная копия. Перечитывается раз в час (сразу — `/reload`).

## Данные и безопасность

- Репозиторий открытый: в коде нет токенов, телефонов, адресов. Токены — только в `bot.env`.
- Данные клиентов — только в базе на сервере в России и в чатах сотрудников; в журнал телефоны,
  имена и тексты сообщений не пишутся. Незаконченная анкета живёт только в памяти (6 часов).
- Коды `/owner` и `/join` одноразовые, защищены от подбора (5 попыток в час на человека).
- Службы работают от пользователя `prostranstvo` и могут писать только в `/var/lib/prostranstvo`.

## Настройки `bot.env`

`BOT_TOKEN` (Telegram), `MAX_TOKEN`, `MAX_BOT_URL` (заполняется сам), `TELEGRAM_COLLECT_CONTACTS`,
`STAFF_DEFAULT_CHANNEL` (`max`), `SITE_URL`, `OWNER_CODE`, `CONSENT_VERSION`, `ADMIN_IDS` /
`MAX_ADMIN_IDS` (постоянные менеджеры по id — обычно не нужно), `OPERATOR_NAME` (для текста согласия
без сайта), `YANDEXGPT_ENABLED=0` + ключи — заготовка (выключена): черновик видит только
сотрудник, клиенту автоматически ничего не уходит (см. `yagpt.py`).
После правки: `systemctl restart prostranstvo-bot prostranstvo-max`.

## Ограничения

- Фото и файлы не пересылаются между мессенджерами (клиенту из Telegram — только текстом из MAX
  и наоборот); сотрудник видит пометку, где их посмотреть.
- В MAX один список команд на всех (клиентский); меню сотрудника — кнопками по `/start`.
- Незаконченная анкета хранится только в памяти: если служба перезапустилась посреди анкеты,
  её нужно начать заново.
