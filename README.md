# Ветка outbox — исходящие письма «Наш декор» с zapros@

Здесь лежат только **зашифрованные** письма (`outbox/<id>.json`). Прочитать их может лишь сервер магазина:
закрытый ключ хранится в базе CRM, открытый — `KEY.pub` (он же https://crm.nashdekor.ru/api/outbox/key).

Сервер раз в минуту забирает ветку и отправляет новые письма от «Наш декор <zapros@nashdekor.ru>»,
ответы приходят в info@. Каждое письмо уходит один раз. Статус — https://crm.nashdekor.ru/api/outbox/status/<id>,
список и настройки — CRM → Ещё → Исходящие.

Написать письмо:

    python3 tools/send.py --to lab@example.ru --subject "Тема" --body-file письмо.txt [--attach файл.docx]
    git add outbox && git commit -m "письмо" && git push origin outbox

Паролей и открытого текста писем в этой ветке нет и быть не должно.

## Ответы на письма — Claude читает сам

`READER.pub` — открытый ключ Claude для чтения ответов (меняется с каждым его сеансом: `python3 tools/replies.py key --new`).
Сервер отдаёт по адресу https://crm.nashdekor.ru/api/outbox/replies только письма в info@, которые пришли в ответ
на письма с zapros@ (ссылаются на них, с тех же адресов или доменов, кроме бесплатных почт, с той же темой) —
и только шифром для этого ключа. Письма клиентов и zakaz@ — никогда. Выключается в CRM → Ещё → Исходящие.
Из облака шифр снимает workflow `replies-fetch` (ветка domain-check, файл pages/replies.txt) → ветка `replies`.

    python3 tools/replies.py read replies.json --out ответы/ [--json ответы.json]

С 19.11.2026 (CRM с «Claude ведёт дизайнеров») сюда же попадают письма дизайнеров из «Базы дизайнеров», которым уже
писали любым каналом (из карточки CRM — Юлия или Михаил, в Telegram, звонком): у такого ответа строка «Дизайнер: Д03 …».
Тот же workflow снимает сводку базы — https://crm.nashdekor.ru/api/dz/export → `dz.json` в ветке `replies`
(карточки, касания, кому отправили модели и сколько раз скачали, тексты писем), тоже только шифром для READER.pub:

    python3 tools/replies.py dz dz.json --out база.json

## Документы в CRM

`python3 tools/doc.py --folder "Сертификаты и ТУ" --title "Название" [--until ГГГГ-ММ-ДД] [--note "…"] файл` →
`docs/<id>.json` (шифр). Сервер кладёт файл в CRM → Ещё → Документы (один раз), статус по id — saved.

## База дизайнеров в CRM

`python3 tools/dz.py leads.json [--settings settings.json] [--title "…"]` → `dz/<id>.json` (шифр). Сервер загружает
карточки в CRM → Ещё → «База дизайнеров» (один раз): новые — целиком, у существующих дописывает пустые поля;
контакты и статусы, которые вписали люди, не трогает. Статус по id — saved («добавлено N, дополнено M»).

В том же конверте (`kind: "dz"`, `items` можно пустой) — отметки Claude:
`"replies": [{"code": "Д03", "channel": "email", "result": "interest|question|later|refused", "comment": "…"}]` — дизайнер
ответил (CRM сама ставит статус и следующий шаг, как кнопка «Ответили?» в карточке);
`"marks": [{"code": "Д06", "touch": "заметка в историю", "channel": "note", "status": "…", "next_step": "…", "next_at": "ГГГГ-ММ-ДД"}]`.

Письмо дизайнеру — обычным `tools/send.py` с отметкой карточки: `--from mikhail --dz Д03:m2` (m1 — первое, m2 — напоминание,
reply — ответ). Перед отправкой сервер проверяет карточку: адрес тот же, не закрыта, для m2 — статус ещё «Написали» и писем
меньше двух, и дизайнер не писал в info@ после нашего касания; иначе письмо не уходит (статус skipped, причина в error).
После отправки в карточке — касание «Письмо» от Claude и следующий шаг (m1 → напоминание через 3 рабочих дня,
m2 → «Напомнили», дальше Telegram или звонок).
